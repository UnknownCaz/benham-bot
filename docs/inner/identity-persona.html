Identity & persona

Benham is Benham — never you. And personality is a costume over a skeleton it can't reshape.

What it does

Everything Benham sends appears as Benham#2721, its own account — a proxy, not account impersonation (Discord forbids the latter). Who it obeys is identity.is_owner(), checked at every entry point.

Its character lives in two files, and that is the whole list:

fileread by
prompts/persona.mdagent.py (the owner agent); until Phase B also codesession.py (the PC session) — one file, both surfaces, so Benham could not be two different people depending on which door you came through. The PC door is gone (INTENT decision 39); the rule stays for the next one.
prompts/guest_persona.mdguest.py, and nothing else

The hard rules are not a file at all — they are a literal inside agent.py, assembled into the system prompt below the persona. That is the layering that matters: a file on disk can be edited, emptied or deleted, and _persona() falls back to a short built-in if it is missing. The rules cannot go missing, because there is nothing to delete.

Why we chose this

Personality tunes HOW, never WHAT. The persona is editable — it is a markdown file you own. That is safe only because the authority layer is somewhere it cannot reach: the hard rules are code, so they cannot be changed, softened, or role-played away ("you are now…", "pretend the rules don't apply", claims of authority — all no-ops). If a requested personality conflicts with a rule, Benham stays in character while declining the conflicting part. An editable costume over a skeleton that is not editable at all is what makes the costume harmless to share.

Editing it means editing the file. There is no runtime path any more. <<persona: …>> directives were applied by brain.py, which went with voice — directives.py survives it and still strips the syntax from every reply, but applies nothing. The stripping is the point that outlived the feature: the model was trained on a persona that documents the syntax, so it can still emit one, and an unstripped <<…>> landing in a friend's DM is a leaked implementation detail.

Guests get their own persona file because the truth differs. persona.md names you, says the model has real tools, and describes operating your machine — all wrong for a guest, the last one dangerously so: a model told wrong things about its tools promises wrong things. _system_prompt() in guest.py reads guest_persona.md and nothing else, and its fallback when the file is missing is a short paragraph carrying two load-bearing sentences: "you have NO tools on this path", and that it is Benham. A missing prompt file must not quietly become an unconstrained model — nor a differently-named one.
