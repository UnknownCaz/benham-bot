Webhook identity

The one way of posting that isn't Benham at all — deliberately outside every gate this manual describes, and worth understanding for exactly that reason.

What it does

benham.py webhook posts via a saved webhook URL: no gateway, no bot token, no benham/bot.py — it works while the bot is stopped. The post wears the webhook's own name and avatar (overridable per post with --username), configured per channel in webhooks.json. It exists because Benham is only in Testing and Chillbar, while the Isle of Berk changelog channel is in a server it was never invited to — send_message physically cannot reach it; a webhook can. Usage: Outer → CLI → Webhooks.

Why we chose this

Why it's outside the chokepoint rather than wired through it: the chokepoint's gates reason about Benham's capabilities in Benham's servers. A webhook is a different thing — the URL is the credential, Discord-side, and anyone holding it can post regardless of what policy.py thinks. Routing it through the policy engine would dress a bare credential up as a governed capability — a gate that looks like it decides something it can't actually stop. The honest design is the one that says: this is a raw tool, treat the URL like a password (gitignored, --list never prints it).

The cost is a hole in the audit trail, accepted with eyes open. A webhook post writes no log line anywhere — bot.log will not show it, no outbox pair exists. The mitigations are structural instead: nothing in the codebase calls it (it's a human-run script only), and the agent can't reach it — only a pc_task shell command could, which needs a DM origin, an untainted turn, and a per-command approval naming the full command. So the model never posts under a webhook face without you reading the exact command that does it.

The identity line it respects: a webhook face is still never you — same rule as everywhere: Benham's surfaces are proxies with their own names, not impersonation of your account. See Identity & persona.

The exaroton watchdog is the other resident outside the walls, with a narrower excuse: fixed, code-authored alert text with no model in the loop — Exaroton.

Paper trail

Honestly: none, and that's the documented trade. The Discord channel itself is the only record of a webhook post. python benham.py webhook --list shows what's configured (names and labels, never URLs); webhooks.json is the gitignored source of truth. If a post needs an audit trail, don't use this path — use benham.py send into a channel Benham is actually in.
