Web search

Both you and guests can ask for live information. Neither search fetches a single byte from your machine — and every search is a stranger talking.

What it does

One implementation (shared_tools.py), consumed by both lanes. It's Anthropic's server-side search tool: it executes on their infrastructure, nothing is fetched from your machine or network, and there's no tool-result loop in guest code for a model to steer. Owner: agent.web_search (on), searches_per_turn 3, no quota, always logged. Guest: searches_per_turn 2, and a searched turn counts double against the daily cap.

Why we chose this

One module because two implementations drift. The tool block, query extraction, and log format lived inline in guest.py; extracting them (Stage 0) meant the owner lane gained search from code already proven on the riskier lane.

Two log files because one typo apart is too close. agent_searches.jsonl and guest_searches.jsonl are separate for the same reason guest memory is a separate file — prefixed keys in a shared file are one bug from crossing streams.

A searched turn is tainted. A web page is text a stranger wrote, cheaper to publish than a Discord message is to post. The subtle part (caught by test, not intuition): taint is set before the response's tool calls run, because server-side results arrive inside the same response that chose to search. Details: The taint model.

Why guests' searches cost double: the search is a second API round trip, so it's priced like one — an honest ledger, not a punishment. And logging every query isn't surveillance theater: search is the one guest surface that sends text out to the world; the log is what makes "don't ask me to google anything weird" enforceable after the fact.
