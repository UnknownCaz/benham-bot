When it asks to confirm

Destructive actions (delete / purge / kick / ban) and role changes always come back as a preview + token first. For a role change, "yes" fires it. For delete / purge / kick / ban there is no bare yes — say what you are confirming ("yes, purge that channel") or name the token. Previews expire — on this DM path that is confirm.conversation_ttl_seconds, 10 minutes, not the hour confirm.ttl_seconds gives the other paths. Expired = cancelled, never assumed yes. Anything that is not a recognised yes or no counts as neither, so an ambiguous reply never fires anything.

Changed 2026-08-17. This paragraph used to say a bare "yes" without the token does nothing "on purpose". It did fire, on every tier — the claim was simply wrong. It is true now for tier 3 only, and by a better rule than the one it described: the yes has to name the action, not quote a hex token. See the confirm flow.

"Why is it asking approval for a normal send?" The turn is tainted — Benham read something a non-owner wrote: a channel, a nickname, a forwarded message, or a web search result. Outward actions then need your yes. Not a bug. Want it free again? Ask in a fresh message that doesn't read stranger content first. The reasoning lives in Inner → The taint model.
