Tray, restart & supervision

Two logon Scheduled Tasks keep Benham alive and visible: benham-bot (the supervisor) and benham-bot-tray (the icon). Only one of them matters to the bot's survival.

The tray icon

tray_bot.ps1 is a monitor, not the supervisor — it polls every 5s and owns no state. Closing it changes nothing about whether the bot runs.

iconmeaning
greysupervisor not running — nothing will restart the bot
greensupervisor running, bot up (tooltip shows pid + uptime)
redsupervisor running, bot down — a restart is presumably in flight

Menu: restart bot (via the supervisor, so there's one restart path rather than two), start/stop supervisor, open supervise.log, full status, hide the icon. The guest-chat item is one-way: it can turn guest chat OFF (fail-safe, worth a panic button) and cannot turn it ON — that stays a deliberate control.json edit.

Windows 11 hides new tray icons — it lands in the overflow behind the taskbar's ^ chevron; drag it onto the taskbar to pin it.

Restarting

Get-ScheduledTask benham-bot        # Ready = armed, Running = supervising now
Start-ScheduledTask benham-bot      # start without waiting for a logon
Stop-ScheduledTask  benham-bot      # stop supervising (does NOT stop a bot already up)

Easiest full restart: tray icon → restart bot. To run in the foreground instead (python -u -m benham.bot), stop the task first — otherwise the supervisor restarts the one you just stopped, or refuses to start alongside yours.

Supervision

supervise_bot.ps1 keeps exactly one benham.bot alive (supervise_bot.bat is the hand-run entry point for the same script). Four behaviours worth knowing:

Runs windowlessthe task action is conhost.exe --headless powershell.exe … — the obvious -WindowStyle Hidden silently doesn't work on Win 11 (Windows Terminal ignores it and puts a window in Alt+Tab). Nothing is lost: every line goes to supervise.log, and the tray is the thing meant to be looked at.
Gives up on a crash loopfive consecutive exits each under 60s = a bot that cannot start (bad token, import error). Backs off 10s → 20s → 40s… to 5 min, then stops and says why. Restart the task (or log back in) to reset.
Refuses to be the second instanceone token with two gateways = duplicate replies and duplicate outbox actions. Named mutex against another supervisor, process check against a hand-started bot — either way it logs the conflict and exits rather than connecting.
Its log rotatessupervise.log → supervise.log.1 past 5MB, one generation.

The limit it cannot cover: if the machine sleeps, the supervisor sleeps with it.

Boot logs

Boot captures (boot<N>.out / .err) live in logs/ with everything else since the source reorg; under the current supervisor all bot output goes to logs/supervise.log, so new pairs are rare. benham.py usage and benham.py status read logs/; pruning it is what actually discards history.
