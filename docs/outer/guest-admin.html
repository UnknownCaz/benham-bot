Guest admin

Guests = whitelisted friends who can DM Claude-through-Benham. Today: chat + web search only — zero client tools, zero Discord reach, zero PC reach. The why lives in Inner → The guest system.

The kill switch

To cut someone off now: remove their id + bounce the bot. Restart IS the kill switch — control.json is read once at import, so enabled: false or a removed id does nothing to a running process. The tray icon menu can also turn guest chat OFF entirely (panic button) — it deliberately cannot turn it back ON; that stays a hand-edit to control.json.

After changing what guests can reach, clear their memory

A restart reloads config and code. It does not reload what the model already said. Guest history keeps text pairs, so anything Benham asserted while a feature was broken stays in the conversation and it will keep deferring to its own past words over the fresh system prompt — being consistent with a mistake.

Seen live on 6 Aug 2026: before the Stage 5 name fix, Benham told a guest “benham-beta isn't actually shared with you”. After the fix it read shared channels fine and still repeated the shortened list, because seven turns of its own history said so.

python benham.py guest forget <user_id>   # one guest
python benham.py guest forget-all             # everyone

No restart needed — memory is read live. Make it the routine last step whenever you grant, revoke, or fix anything a guest can reach: config → restart → clear memory. Wrong code is fixed by a restart; wrong statements are sticky.

Workspace flip LIVE

Stage 4 of the guest refactor: guests get files. Live since 6 Aug 2026 with all six granted. The procedure, for reference or for re-doing it:

  1. Set guest.mode: "workspace" with capabilities: [] and soak it a while — behaves exactly like chat, proves the plumbing.
  2. Add some of ws_list, ws_read, ws_write, ws_delete, ws_import, ws_attach to guest.capabilities + restart.
  3. Check the boot banner — it prints the live grant list; confirm it says what you meant.
  4. Update guest_guide.md so guests aren't surprised.
  5. Clear guest memory — otherwise they carry the old answers.

What they get: guest_work/<their_id>/ each (20MB, 100 files, flat names, nothing runnable) plus read-only guest_work/commons/ that you fill by hand — drop files in anytime, no restart needed, files are read live.

Shared channels CODE SHIPPED · OFF

Stage 5: guests can read Discord channels you list, through read_shared_channel — a separate capability, never a grant of the owner's read_channel. Two independent switches, both yours, and either one empty means nothing is readable:

  1. Grant read_shared_channel in guest.capabilities.
  2. List channel ids in guest.read_channels.
  3. Restart, then clear guest memory.

Guests can ask what's shared and get back only the ids already on the list — the capability refuses anything else before it resolves the channel, so it cannot be used to discover what other channels exist, and a refusal names nothing but the id that was asked for.

Listing a channel publishes it. Everything in it, past and future, becomes readable on demand by every guest on the allowlist — and the people posting there won't know. Testing Server channels are the safe choice; a friend-server channel is a consent question before it is a config one.

Code runs CODE SHIPPED · OFF

Stage 6: guests can run Python and shell commands — on Anthropic's servers, in their sandbox, never on your machine. The container has no internet, cannot see your disk, the guest workspace, or Discord; it starts empty every time and is thrown away after. There is nothing to gate, only to record and bill.

Turn on with guest.code_execution: { "enabled": true, "runs_per_day": 10 } + restart. Each sub-tool call charges one message and one run, and lands in guest_runs.jsonl. When a guest's daily runs are spent the tool is simply not offered that turn — a withheld tool reads as “I can't right now”, where one that always errors invites a retry loop you pay for.

No bridge. Files made in the container do not come back to guest_work/, and workspace files are not uploaded to it. That was a deliberate V1 choice — revisit once there are real use cases.

Anthropic bills container time: 1,550 free hours/month per org, then $0.05/hour. It is free entirely on requests carrying web_search_20260209 or later, which this build does not use yet — worth revisiting if runs get popular.

Every guest message bills you — that's what the caps are for. Caps reset on the first message after midnight. Reservation happens under a lock, so two concurrent turns can't both spend the same remaining message; a failed turn is refunded.
