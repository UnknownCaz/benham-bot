The kill switch

To cut someone off now: remove their id + bounce the bot. Restart IS the kill switch — control.json is read once at import, so enabled: false or a removed id does nothing to a running process. The tray icon menu can also turn guest chat OFF entirely (panic button) — it deliberately cannot turn it back ON; that stays a hand-edit to control.json.

Workspace flip CODE SHIPPED · OFF

Stage 4 of the guest refactor: guests get files. The code is in; nothing is granted until you flip it. The procedure, in order:

  1. Set guest.mode: "workspace" with capabilities: [] and soak it a while — behaves exactly like chat, proves the plumbing.
  2. Add some of ws_list, ws_read, ws_write, ws_delete, ws_import, ws_attach to guest.capabilities + restart.
  3. Check the boot banner — it prints the live grant list; confirm it says what you meant.
  4. Update guest_guide.md so guests aren't surprised.

What they get: guest_work/<their_id>/ each (20MB, 100 files, flat names, nothing runnable) plus read-only guest_work/commons/ that you fill by hand — drop files in anytime, no restart needed, files are read live.

Caps & spend

capvaluewhere
per-guest daily messages100the guest block in control.json

Every guest message bills you — that's what the caps are for. Caps reset on the first message after midnight. Reservation happens under a lock, so two concurrent turns can't both spend the same remaining message; a failed turn is refunded.
